# CPU仕様（草案）

## 1. 目的

CPUは `GameEngine` と同じ公開操作を使って行動する。CPU専用のルール分岐は作らない。

## 2. 初期版の行動

各合法手について、タイルの位置・回転・コマ配置の有無を候補として評価し、最も評価点が高い候補を選ぶ。同点はシード付き乱数で選ぶ。

## 3. 評価項目

| 優先度 | 項目 | 例 |
| --- | --- | --- |
| 高 | 即時得点 | 都市や道を完成させる |
| 高 | コマ回収 | 自分のコマが戻る完成を優先する |
| 中 | 将来性 | 開いた辺が少なく、完成しやすい地形を作る |
| 中 | 妨害 | 相手が得点化しやすい地形を不用意に完成させない |
| 低 | 盤面整理 | 配置可能な辺を残す |

## 4. 難易度

- `easy`：合法手からランダム選択。
- `normal`：即時得点とコマ回収を評価する。
- `hard`：将来性・相手への影響も評価する。

MVPでは `easy` と `normal` のみ実装対象とする。

## 5. 制約

- CPUの思考時間は通常1秒以内を目標とする。
- 候補が多い場合は、タイル配置候補を先に絞り込んでからコマ配置を評価する。
- CPUが出した操作も必ず通常のルール検証を通す。

## 6. CPU高速化

ソロ対戦中は、プレイヤーがCPUの操作演出・待機時間を短縮できる。これは表示と進行速度の設定であり、難易度や評価関数を変更しない。

将来、思考時間の上限を調整する機能を導入する場合は、CPU高速化とは別に「思考量」または難易度として表示する。
