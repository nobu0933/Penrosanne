# Penrosanne アーキテクチャ仕様（草案）

## 1. 方針

ゲームのルール、CPU、通信、描画を分離する。特にゲームルールはブラウザやネットワークに依存しないため、ローカル対戦・CPU戦・オンライン対戦で同じ `game` モジュールを再利用できる。

## 2. ディレクトリ構成

```text
src/
├── game/
│   ├── GameState.js
│   ├── GameEngine.js
│   ├── Tile.js
│   ├── TileSet.js
│   ├── Board.js
│   ├── Player.js
│   ├── Scoring.js
│   └── Rules.js
├── ai/
│   └── CpuPlayer.js
├── network/
│   ├── Host.js
│   ├── Client.js
│   └── Protocol.js
├── ui/
│   ├── BoardView.js
│   ├── PlayerPanel.js
│   ├── GameUI.js
│   └── GameSetupUI.js
└── main.js
docs/
tests/
```

オンライン対戦を実装する段階で、Node.jsで動かすホスト用コードは `server/` に分離することを検討する。

## 3. モジュール責務

| モジュール | 責務 |
| --- | --- |
| `GameState` | 不変または安全に複製可能なゲーム全状態 |
| `GameEngine` | 手番進行、操作受付、状態遷移、イベント発行 |
| `Tile` | タイル種別、辺ごとの地形、内部の特徴領域、辺矢印パターン、回転後の情報 |
| `TileSet` | タイル定義から山札を生成する |
| `Board` | 直交座標の配置済みタイル、辺矢印・地形の接続、隣接検索、連結領域検索。辺一覧を盤面更新までキャッシュする |
| `TileTheme` | テーマ別の透過PNGを遅延読み込みし、タイルの地形レイヤーを回転・ミラーに追随して描画する。欠損画像はCanvas描画へフォールバックする |
| `Player` | プレイヤー情報、得点、残コマ、種別（人間／CPU） |
| `Rules` | 合法手、コマ配置可否、完成判定 |
| `Scoring` | 完成・終局時の得点計算 |
| `CpuPlayer` | 状態を評価してゲーム操作を選ぶ |
| `Host` | 対戦ルームとゲーム状態の管理、操作検証・配信 |
| `Client` | ホスト接続、操作送信、状態同期 |
| `Protocol` | ネットワークのメッセージ種別とペイロード定義 |
| `BoardView` | Canvas/SVGによる盤面描画、配置候補表示、マウス／タッチのスナップ操作 |
| `PlayerPanel` | 手番・得点・コマ数の表示 |
| `GameUI` | 画面遷移、操作入力、各UI部品の統合 |
| `GameSetupUI` | モード・ルール・テーマなど、開始前設定の入力と検証 |

## 4. 依存方向

```text
ui ────────┐
ai ────────┼──> game
network ───┘
main ─────────> ui / game / network
```

- `game` は `ui`、`ai`、`network` を import しない。
- `ui` と `network` は `GameEngine` の公開APIだけを使う。
- CPUも人間と同じゲーム操作（タイル配置、コマ配置、手番終了）を使う。

### 空白防止判定のキャッシュ

このキャッシュは、ルール上の「禁則配置」判定を高速化する実装であり、デッドエンドの完全な検出を保証するものではない。

- 各空き辺について、(1) シンまたはファットが重ならずに入る物理的証人、(2) さらに矢印まで合う証人、の有無をキャッシュする。
- タイル配置後は、新タイルの辺と中心から辺長の約3倍以内にある空き辺だけを再検査する。
- 手番タイルの候補は、地形・重なりを満たす配置を基準に、空白防止キャッシュで通常・相対禁則・絶対禁則へ分ける。絶対禁則は除外し、相対禁則は未使用のプレイヤーにだけUIへ返す。矢印不一致の候補は、3辺以上が既存タイルと接する場合だけ別枠で返す。
- 近傍辺でも、既存の候補がまだ合法なら再探索しない。離れた空き辺は前回の結果を利用する。
- キャッシュ有無で候補集合が一致することをテストで保証する。

## 5. 状態遷移

`DRAW_TILE` → `PLACE_TILE` → `PLACE_MEEPLE` → `SCORE_COMPLETED` → `NEXT_TURN`

UIは現在フェーズに応じた操作だけを提示する。オンラインではホストが各フェーズの妥当性を検証する。

## 6. 状態の保存と再現性

- `GameState` はJSONにシリアライズ可能なデータだけで構成する。
- `GameConfig` は対局開始時に確定し、開始後は不変として扱う。テーマなど表示専用の設定も同期・保存対象に含める。
- 乱数にはシードを持たせ、同じシードと操作履歴から同じ対局を再現できるようにする。
- オンライン同期では、原則としてホストが送る確定状態または操作イベントを使用する。
