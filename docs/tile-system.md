# ベンローズタイルシステム仕様（草案）

## 1. 目的

ベンローズタイルの見た目、回転、辺の接続、隣接関係を、ゲームルールから利用できるデータとして表現する。

## 2. 初期採用形状

初期版は、次の2種類のペンローズひし形だけを使用する。

| 種別 | 識別子 | 内角 | デフォルトの向き | 頂点の順序 |
| --- | --- | --- | --- | --- |
| 薄いひし形（シン） | `thin` | 36度・144度 | 横長 | 最上部の144度頂点を `A` とし、反時計回りに `B`、`C`、`D` |
| 厚いひし形（ファット） | `fat` | 72度・108度 | 縦長 | 最上部の72度頂点を `E` とし、反時計回りに `F`、`G`、`H` |

初期版では凧形・矢尻形は使用しない。見た目のタイル形状と、ゲーム上の接続情報は分けて保持する。描画は `BoardView`、合法性判定は `Board` と `Rules` が担う。

## 3. 形状マッチングと配置制約

頂点色（白・赤・青）は合法配置に使用しない。地形の接続判定とは独立して、以下の3つの形状規則をすべて満たす必要がある。候補表示はこの全条件を満たす通常候補だけであり、相対禁則配置・3辺接続時のマッチング無視候補は存在しない。

### ルール1：絶対禁則

手元タイルを置いた後、盤面のすべての空き辺について、シンまたはファットの少なくとも一方を**既存タイルと重ならずに**隣接配置できなければならない。地形や辺記号はこの物理的な空白防止判定に含めない。満たせない候補は表示しない。

### ルール2：辺記号

各辺には、次の記号を持たせる。隣接辺は同じ系列（`alpha` または `beta`）で、`convex` と `concave` が反対の場合だけ接続できる。

| 形状 | 辺 | 記号 |
| --- | --- | --- |
| シン | `CD` | `alpha-convex` |
| シン | `DA` | `beta-convex` |
| シン | `AB` | `beta-concave` |
| シン | `BC` | `alpha-concave` |
| ファット | `GH` | `alpha-concave` |
| ファット | `HE` | `beta-convex` |
| ファット | `EF` | `beta-concave` |
| ファット | `FG` | `alpha-convex` |

開始時に「通常・180度回転を判定」を選ぶ場合、未配置タイルは通常と、辺記号だけを180度回転した両方のパターンを試し、周囲の全隣接辺と整合するパターンだけを可能性として保持する。180度回転ではシンは `A↔C`・`B↔D`、ファットは `E↔G`・`F↔H` を入れ替える。可能性が1つだけになった時点でそのパターンを確定する。「通常のみ」を選ぶ場合は通常パターンだけを使う。この回転は地形やプレイヤーの左右反転操作とは別の概念である。

手札は未配置である限り辺記号パターンを確定しない。候補を表示するたび、通常・180度回転の両方を改めて判定し、以前の候補探索結果を手札へ持ち越さない。

### 地形の左右反転

開始時設定の地形左右反転が `unlimited` の場合、未配置タイルは通常地形と左右反転地形の両方を候補生成する。左右反転は辺記号パターンと地形180度回転のどちらとも独立である。したがって、地形については通常・左右反転のみ・180度回転のみ・左右反転かつ180度回転の4状態を評価する。反転に伴い、辺地形、都市・道・草原の特徴領域、道路終端、草原小領域、ミープルアンカーを同じ変換で移す。

`once` の場合は、各プレイヤーが未配置タイルを1回だけ左右反転できる。反転後の手札については、通常と同様に地形180度回転・辺記号パターンを判定する。

通常・180度回転を判定するモードでは、隣接辺だけでは一意に決まらないタイルのパターンを、最初に見つかった向きへ固定しない。両方の可能性を保持し、以後の辺記号・頂点型との整合性で候補を絞り込む。たとえば時計回りの `AA` が deuce 型を定める場合、後から必要になる E を置ける向きが残るように判定する。

### ルール3：頂点型

各盤面頂点では、その周囲を時計回りに読んだタイル頂点名が、次の循環順列のいずれか、またはその連続部分列でなければならない。

| 型 | 順列 |
| --- | --- |
| sun | `GGGGG` |
| moon | `EEEEE` |
| king | `GGGGBD` |
| queen | `GGBDGBD` |
| jack | `EEEA` |
| ace | `HFDGB` |
| deuce | `AAE` |
| star | `FHC` |

順列は循環する。たとえば `BDGGB` は queen の循環順列 `BDGGBDG` の先頭部分なので許可され、残る108度は `DG` の順でしか埋められない。候補タイルの4頂点すべてについてこの条件を判定する。

未配置の扇形が複数ある頂点では、空白をまたぐ既存タイル同士を連続した頂点列として扱わない。各タイルが実際に占める角度と頂点型のスロットを照合し、空白には将来の頂点名を補えるものとして判定する。これにより、離れた既存タイルの間に空白を挟む合法候補を誤って除外しない。

### 確定配置の事前探索

手元タイルの地形を判定する前に、盤面の形状制約だけから将来の配置を探索する。これは実際の盤面や山札を変更しない、表示・候補判定専用の仮想盤面で行う。

1. 実盤面のタイル頂点を探索対象とする。事前探索ではルール1（空白防止）・ルール2（辺記号）・地形を判定せず、ルール3の頂点型だけを用いる。
2. 時計回りの**連続して接する**頂点列を、`C`、`AA`／`FH`／`HF`／`BH`／`FD`、`AEE`／`EEA`／`EAE`／`DGG`／`GGB`、4枚の `EEEE`／`DGGG`／`GGGB`／`BDGB`／`DGBD`／`DGGB` の優先順に照合する。`DGG` と `GGB` は king・queen のどちらかは未確定だが、全完成形に共通する配置を確定する（それぞれ `GBDGG`、`GGBDG` まで）。各識別列は頂点列全体との完全一致ではなく、連続部分として含まれれば直ちに対応する頂点型を確定する。たとえば `HC` は `C` を含むため star、`GBH` は `BH` を含むため ace とする。対応する頂点型の完成方法を、当該頂点の周囲だけで列挙する。
3. 頂点の「埋まり」は、実際に配置済みのタイルと確定配置の両方を同じ仮想盤面上で数える。完成方法が1つならその全タイルを、複数なら全完成方法に共通するタイルだけを**確定配置**として仮想盤面へ追加する。これにより、`BDGG`／`GGBD` のように頂点型自体は曖昧でも共通の確定部分を追加できる。
4. 新しい確定タイルの4頂点だけを次の探索対象にして繰り返す。確定配置が増えなくなれば終了し、未確定配置は記録しない。

一度頂点型が確定した頂点は、仮想盤面内でその型を保持する。その頂点型に必要な残りの頂点スロットを埋める候補だけで一意性を判定し、周囲をすべて確定配置で埋めるまで連鎖させる。残り1スロットの場合は、その頂点型で要求される頂点名を直接照合して優先確定する（例：`FDGB → ace → H`、`GBHF → ace → D`）。これは star だけでなく、sun・moon・king・queen・jack・ace・deuce・star の全頂点型に共通する。

確定配置探索では頂点キューだけを使う。確定配置は仮想盤面へ追加したまま次ターンへ引き継ぐ。確定配置そのものに実タイルを置いた場合は探索を再実行しない。非確定位置への実配置では、そのタイルを同じ仮想盤面へ追加し、新タイルの4頂点からだけ探索を再開する。

確定配置は盤面上で**薄い灰色の実線枠**で表示する。未確定配置は記録・表示しない。確定配置もゲーム状態上は未配置である。手元タイルの最終候補は通常の地形接続・辺記号・頂点型・空白防止で判定し、確定配置と異なる位置で重なる候補は表示しない。

## 4. タイル定義

各タイル定義は、少なくとも以下を持つ。

```js
{
  id: "thin-road-01",
  shape: "thin",
  vertices: ["A", "B", "C", "D"],
  edges: ["road", "field", "city", "field"],
  features: [
    { id: "road-a", type: "road", edgeIndexes: [0] },
    { id: "city-a", type: "city", edgeIndexes: [2] },
    { id: "field-a", type: "field", edgeIndexes: [1, 3] }
  ]
}
```

`edges` は、各形状で定めた最上部頂点から反時計回りに進む辺の順序と一致させる。地形がタイル内で分岐・連結する表現は、最初の描画プロトタイプとともに確定する。

## 5. 回転

- 初期版では、スナップにより決まる正しい向きを基準とする。180度回転しても合法な場合だけ、もう一方の向きを選べる。
- 回転後は、辺番号・頂点・内部地形の対応を同じ規則で変換する。
- 反転は通常行わない。開始前設定で追加ルールが有効な場合だけ、各プレイヤーは対局中1回、未配置タイルを反転できる。

プレイヤーが使う左右反転は地形カードの操作であり、`edgeTerrain`、特徴領域、草原小領域、道路終点、アンカーを左右反転する。一方、辺記号はタイル形状に属するため左右反転では変えない。辺記号の状態は通常／180度回転パターンだけで独立して判定する。

### 辺記号・地形パターンの独立した180度回転

配置前の手元タイルは、通常状態に加えて、開始前設定で有効な場合は次の状態を候補として持つ。

1. 通常
2. 辺記号だけを180度回転
3. 地形だけを180度回転
4. 辺記号と地形の両方を180度回転

地形の180度回転はタイルの輪郭、重心、盤面上の `rotation` を変えない。`edgeTerrain`、`featureGroups` の辺名、`roadTerminals` の辺、`fieldScoreGroups` の小領域（①↔③、②↔④）、および `featureAnchors` の座標を同時に変換する。都市・道・草原グループの配列添字は保つため、各グループIDを参照する得点・ミープル情報はそのまま対応する。

### タイル種別ごとの初期回転

次のタイル種別は、初期向きを180度回した状態の**辺・特徴領域・道路終点・草原小領域・アンカー座標を直接定義する**。実行時に初期回転の変換は行わない。これはプレイヤーが行う回転や左右反転とは別である。

- `curve-road-v`
- `city-one-side-curve-road-c-reverse`
- `city-road-end-c-reverse`
- `t-junction`
- `city-three-connected`
- `city-three-connected-reverse`
- `city-three-road`
- `city-three-road-reverse`
- `monastery-road-end-reverse`

## 6. 盤面表現

盤面は直交座標系で保持する。以下の情報を保持する。

- タイルの一意な配置ID
- タイル種別と回転
- タイルの重心座標（`centerX`, `centerY`）
- 多角形の頂点座標
- 各タイルの辺記号パターン候補（通常／180度回転）と、候補が1つになった場合の確定値
- 各辺と、接続先タイルの辺の対応

タイルは「重心座標」「回転」「形状」から4頂点の座標を算出する。頂点座標を保存する場合も、重心・形状・回転から再計算できる値として扱う。浮動小数点の誤差を避けるため、接続判定では正規化済みの座標または離散化された頂点・辺IDを用いる。

### 基準サイズと数学座標

タイルの辺長を `s` とする。PCでの初期表示時は `s = ブラウザ表示領域の高さ / 5` とする。ただし、画面の縦横比や盤面の余白により見切れる場合は、盤面表示側で縮小してよい。ゲーム内部の座標はCSSピクセルに依存しない盤面単位を使い、描画時に拡大率を掛ける。

各タイルのローカル座標は重心を原点 `(0, 0)` とする。画面座標は `x` が右方向、`y` が下方向に増えるものとする。

#### シン（横長）

`a = s × cos(72°)`、`b = s × sin(72°)` とする。

```text
             A (0, -a)
            /         \
 D (-b, 0)               B (b, 0)
            \         /
             C (0, a)
```

| 頂点 | ローカル座標 |
| --- | --- |
| A | `(0, -a)` |
| B | `(b, 0)` |
| C | `(0, a)` |
| D | `(-b, 0)` |

このときA・Cの内角は144度、B・Dの内角は36度であり、辺長は常に `s` となる。

#### ファット（縦長）

`a = s × cos(36°)`、`b = s × sin(36°)` とする。

```text
             E (0, -a)
            /         \
 H (-b, 0)               F (b, 0)
            \         /
             G (0, a)
```

| 頂点 | ローカル座標 |
| --- | --- |
| E | `(0, -a)` |
| F | `(b, 0)` |
| G | `(0, a)` |
| H | `(-b, 0)` |

このときE・Gの内角は72度、F・Hの内角は108度であり、辺長は常に `s` となる。

各ローカル座標を回転角 `θ` で回転させて重心座標へ加算し、盤面上の頂点座標を得る。

```text
x = centerX + localX × cosθ - localY × sinθ
y = centerY + localX × sinθ + localY × cosθ
```

## 7. 配置候補の表示と操作

タイルを引いた時点で、まずルール3の頂点型だけから確定配置を増分探索する。確定配置だけを薄い灰色の実線枠で表示し、未確定配置は探索・表示しない。次に、現在のタイルについて地形・重なり・絶対禁則・辺記号・頂点型を満たす既存どおりの操作可能候補を表示する。ただし確定配置と異なる位置で面積が重なる候補は除外する。手元からドラッグしたタイルが操作可能な候補の近くに来たときは、その候補の位置へスナップし、地形模様を含む実物表示に切り替える。

### PCのポインター操作

- 引いたタイルは、画面中央下の手元に表示する。
- 手元のタイルを左クリックでドラッグして盤面へ移動する。
- 配置候補の近くへ来ると、タイルを正しい角度・位置へ自動スナップする。
- スナップ中に左クリックを離すと仮置きする。仮置きはゲーム状態へはまだ反映しない。
- 仮置き後、手元には「やり直す」ボタンを表示する。押すとタイルは手元に戻る。
- 同じ位置で180度異なる配置も合法な場合だけ、仮置き中に回転ボタンを表示する。
- 「配置を確定」を押したときだけ、タイル配置をゲーム状態へ反映する。

ミープルを置ける領域は盤面上のマーカーで表示する。草原は四角、都市・道・修道院は丸で表す。マーカーのクリックで配置し、ミープルのドラッグ操作は行わない。アンカー座標はタイル回転に追随する。

マーカーへホバーしたときは、その特徴領域だけを強調する。草原は得点用の①〜④小領域単位で、接続している小領域の草原色だけを淡く変更する。補助線・破線・輪郭・アンカーへ伸びる線は描かない。都市・道を越えてタイル全体を強調してはならない。都市は既存の赤い都市領域だけ、道は既存の茶色い道路領域だけを同じ太さで再着色する。都市は辺から内側へ曲線状の縁を持つ領域として描き、別の都市や非接続の道と中心で接触して見えないようにする。

### タッチ操作

- タイルを回転させず、配置候補の近くまでドラッグすると自動でスナップする。
- 指を離すと配置を仮確定する。
- 180度回転した向きも合法である場合、タップで向きを切り替える。
- 確定ボタンを押して最終的に配置する。

仮置き中はキャンセルして別の候補を選び直せる。UI上の操作補助であり、最終的な合法性判定は `Rules` が行う。

## 8. 初期タイルセットと開始タイル

- 初期タイルセットは、シンとファットの両方を含む。
- 地形は曲がった道、直線の道、交差点、都市、修道院を含む。
- 修道院タイルは「1本だけ道が出ているもの」と「周囲がすべて草原のもの」だけを使用する。
- タイル定義は、1枚ごとにIDと地形情報を持つ配列で管理する。枚数や地形構成をあとから調整できるようにする。
- 開始タイルは山札候補からランダムに1枚選び、盤面へ配置する。
- 開始タイルの辺記号パターンは、周囲にタイルがないため未確定として開始する。最初に隣接するタイルの配置後も、整合するパターンが複数あれば両方を保持し、以後の配置で一意になった時点で確定する。

### 山札種類

- `lite`：36枚。短時間向けで、シン・ファットを18枚ずつ含む。
- `standard`：90枚。タイル一覧（CATALOG）と同じ暫定基本セットで、シン・ファットを45枚ずつ含む。
- `road-only`：42枚。道タイル（直線・曲線の4種）を各形状3枚ずつ、交差点タイル（T字2種・十字）を各形状2枚ずつ、修道院タイル（草原・道終端2種）を各形状1枚ずつ含む。

`createPrototypeDeck(random, deckType)` はこれらの登録済み山札を生成する。ゲーム画面では山札セレクターから選び、「この山札で新しいゲーム」を押して対局を開始し直せる。タイル一覧デバッグ画面は山札種類に依存せず、`MANUAL_FEATURE_ANCHORS` に登録された全タイル種別を同じ登録順で表示する。

### カタログ追加タイル（山札には未追加）

次のタイルはタイル一覧で確認できるが、既存の山札構成は変更しない。`first`〜`fourth` は各形状に割り当てられた辺順を指す。

- `city-one-two-road-ends` / `-reverse`：都市1辺と、都市で終わる独立した道2本。
- `city-road-end-third` / `-reverse`：都市1辺と、都市で終わる道1本。
- `city-opposite-separated-curve-road`：`first`・`fourth` の分離都市と、`second`・`third` を結ぶ曲線道。
- `city-opposite-separated-road-second-to-first` / `-reverse`、`city-opposite-separated-road-third-to-first` / `-reverse`：分離都市2つと、指定都市で終わる道1本。
- `city-opposite-separated-two-road-ends`：分離都市2つと、それぞれの都市で終わる独立した道2本。
- `city-opposite-connected-road-second-end` / `-reverse`、`city-opposite-connected-two-road-ends`：接続都市と、都市で終わる道1本または独立した道2本。
- `monastery-two-road-ends`：中央修道院と、修道院で終わる独立した道2本。

これらの草原小領域は、次の接続セットを使う（`/` は別の草原領域）。

| タイル | 草原小領域 |
| --- | --- |
| `city-one-two-road-ends` | `1,4 / 2 / 3` |
| `city-one-two-road-ends-reverse` | `1,2 / 3 / 4` |
| `city-road-end-third` | `1,4 / 2,3` |
| `city-road-end-third-reverse` | `1,2 / 3,4` |
| `city-opposite-separated-curve-road` | `1,2,4 / 3` |
| `city-opposite-separated-road-second-to-first` | `1,3,4 / 2` |
| `city-opposite-separated-road-second-to-first-reverse` | `1,2,3 / 4` |
| `city-opposite-separated-road-third-to-first` | `1,4 / 2,3` |
| `city-opposite-separated-road-third-to-first-reverse` | `1,2 / 3,4` |
| `city-opposite-separated-two-road-ends` | `1,3 / 2 / 4` |
| `city-opposite-connected-road-second-end` | `1,3,4 / 2` |
| `city-opposite-connected-road-second-end-reverse` | `1,2,3 / 4` |
| `city-opposite-connected-two-road-ends` | `1,3 / 2 / 4` |
| `monastery-two-road-ends` | `1,2,4 / 3` |

### タイル定義の入力項目

タイルセットは、タイル1枚ごとの固定データではなく、同種カードの枚数を持つ定義配列から生成する。各定義では、まず全4辺へ地形のイニシャルを割り当て、その後に同一地形の辺・領域がタイル内でつながるかを定義する。

| 項目 | 型 | 内容 |
| --- | --- | --- |
| `idPrefix` | 文字列 | 種別を表すID接頭辞 |
| `count` | 数値 | 同種カードの枚数 |
| `shape` | `thin` / `fat` | そのタイルのひし形種別 |
| `edgeTerrain` | 辺名をキーとするオブジェクト | 各辺の地形。`C`（都市）、`R`（道）、`F`（草原）のいずれか |
| `featureGroups.city` | 辺名配列の配列 | 同じ都市としてタイル内でつながる辺の組。別配列は分離都市を表す |
| `featureGroups.road` | 辺名配列の配列 | 同じ道としてタイル内でつながる辺の組。交差点では各辺を別配列にする |
| `featureGroups.field` | 領域の配列 | 草原の内部領域。都市・道で区切られた草原は別領域として定義する |
| `fieldScoreGroups` | 小領域番号配列の配列 | 終局時の草原得点・ホバー専用の接続定義。①〜④の小領域をタイル内で接続する組 |
| `fieldScoreCityAdjacency` | 小領域草原グループごとの都市グループID配列 | 得点用草原がタイル内で実際に隣接する都市。`fieldScoreGroups` と同じ添字を使い、他の草原領域の都市を含めない |
| `roadTerminals` | 道グループごとの終端定義 | 各道の終端を `edge`、`city`、`intersection` で表す。道の完成判定に使う |
| `fieldCityAdjacency` | 草原グループごとの都市グループID配列 | その草原がタイル内で隣接する都市を表す。草原の終局得点に使う |
| `hasMonastery` | 真偽値 | 修道院の有無 |
| `hasCrest` | 真偽値 | 紋章の有無 |

辺名は画面上の方向ではなく、両端の頂点名で表す。シンは順に `AB`、`BC`、`CD`、`DA`、ファットは `EF`、`FG`、`GH`、`HE` である。タイルを回転してもこの名前は変わらない。`top`・`right`・`bottom`・`left` は地形データ、接続、終端指定では使用しない。

草原の終局得点・ホバー・ミープル配置時の占有判定では、各ひし形を頂点側の4小領域（①〜④）へ分けて扱う。①は最初の頂点（シンはA、ファットはE）の側とし、反時計回りに②〜④を振る。`fieldScoreGroups` で同じ配列に含めた小領域だけがタイル内でつながる。タイル間では、共有辺の両側が草原または道である場合だけ、共有辺の同じ頂点側にある小領域どうしをつなぐ。都市辺をまたいだ接続はしない。

### 左右反転タイル

各通常タイルには、`idPrefix` の末尾へ `-mirror` を付けたミラー版を用意する。ミラー版は山札へ入れず、プレイヤーの反転アクションでだけ手札タイルと置き換える。辺は `first` と `fourth`、`second` と `third` を交換する。アンカーはローカル座標の `x` 符号を反転し、小領域は `①→①`、`②→④`、`③→③`、`④→②` と対応させる。地形の特徴領域・道の終端・草原と都市の隣接情報もこの対応で変換する。

## 9. テーマ画像

テーマ画像は `assets/themes/<themeId>/` に置く透過PNGまたはSVGであり、1枚のタイルを草原、道、交差点、都市、修道院の順に重ねて描画する。画像が存在しないレイヤーは既存のCanvas描画にフォールバックするため、テーマ制作は任意のタイル・領域から段階的に進められる。

テーマ選択の `none` はデバッグ用の無効テーマであり、画像を一切適用せず既存のCanvas描画だけを表示する。対局中でもテーマはいつでも切り替えられる。

盤面と手元の現在タイルには同じテーマレイヤーを適用する。ミープルアンカーはタイル中心を原点とする辺長比のローカル座標で、タイルごとに手動指定できる。草原の従来記法である `featureGroups.field[].anchor` はそのまま使用できるが、現在の試作セットはすべて `TileSet.js` 冒頭の `MANUAL_FEATURE_ANCHORS` で明示指定する。道・都市・草原・修道院の座標はこの一覧を直接編集する。`featureAnchors` があればこちらを優先する。ミラー版ではどちらの座標も `x` を左右反転する。

`MANUAL_FEATURE_ANCHORS` はテーマIDをキーにした `Map` である。`default` は全テーマ共通の基準座標、`none`・`meadow`・`cyber` はテーマ固有の上書き座標だけを持つ。テーマ側に該当タイルがなければ `default` を使う。タイル一覧・デバッグ画面ではテーマを選んで「アンカー位置を調整」をオンにすると、ミープルをドラッグして現在のテーマの座標を一時調整できる。「現在テーマの全アンカーをコピー」で出力される `['themeId', new Map([...])]` を該当テーマのエントリーに貼り付ければ、すべてのタイルの座標を一括反映できる。ブラウザ上の調整値は保存しない。

```js
featureAnchors: {
  city: [{ x: 0.12, y: -0.18 }],
  road: [{ x: -0.08, y: 0.22 }],
  field: [{ x: 0.28, y: 0.04 }]
}
```

`tile-gallery.html` は山札に入るタイル種別を1枚ずつ表示するデバッグページである。テーマを切り替えられ、アンカーをホバーするとゲーム画面と同じ特徴領域を着色する。各行には保存済みの手動座標、または未指定なら現在の自動座標を表示するため、`TileSet.js` の手動調整に使う。

画像は正方形のキャンバスで作成し、画像中心をタイル中心に合わせる。描画時にはタイルの回転とミラー状態を画像へ同じように適用するため、ミラー版専用の画像は不要である。

### ミープル画像

ミープル画像はすべて `56×56px` の正方形SVGを基準にする。盤面の直立・寝そべりミープルは、次の3レイヤーをこの順で重ねる。

1. `*-dark-shadow.svg`（最背面）
2. `*-light-shadow.svg`
3. `*-front.svg`（最前面）

直立用は `meeple-standing-*`、草原用は `meeple-lying-*` を使用する。各レイヤーはグレースケールかつ透明背景とし、ゲーム側でプレイヤー色から前面・明るい影・暗い影を個別に色相／明度調整して着色する。手元の残数表示だけは単層の `meeple-reserve.svg` を使う。旧 `meeple-standing.svg`・`meeple-lying.svg` は元データとして残してよいが、盤面描画には使用しない。

### ファイル名

`<tile-kind>_<shape>_<layer>.png` を使用する。`shape` は `thin` または `fat`、辺の位置はタイル定義の `first`〜`fourth` を `1`〜`4` で短縮する。`tile-kind` はミラー版でも末尾の `-mirror` を除いた通常タイル種別とする。

| レイヤー | ファイル名例 | 内容 |
| --- | --- | --- |
| 草原 | `curve-road-v_thin_field-1.png` | 小領域①の草原 |
| 草原 | `curve-road-v_thin_field-234.png` | 小領域②③④の草原 |
| 道 | `straight-road_thin_road-13.png` | 辺①・③を結ぶ1つの道 |
| 都市 | `city-adjacent-connected-c_fat_city-12.png` | 辺①・②でつながる都市 |
| 交差点 | `t-junction_thin_intersection.png` | 交差点の中心部分 |
| 修道院 | `monastery-field_fat_monastery.png` | 修道院 |

道・都市・草原が複数の特徴領域に分離するタイルでは、それぞれ別画像を用意する。草原は `fieldScoreGroups` の小領域セット、道・都市は対応する特徴グループの辺番号セットをファイル名に用いる。ホバー時は該当PNGの不透明部分だけを色変更する。 

ホバー着色は通常描画の積層順を維持する。草原の着色は草原レイヤーの直後に描くため、後から描かれる道・都市・交差点・修道院の上には表示しない。

### 同梱サンプル

`meadow` と `cyber` には、既存のタイル定義から生成した透過SVGサンプルが含まれる。各テーマの全タイル種別・全分離領域をカバーし、描画順・回転・ミラー・ホバーを確認できる。再生成する場合は `npm run generate:sample-themes` を実行する。生成処理は既存ファイルを上書きしないため、制作済み画像は保護される。

同梱サンプルテーマはSVGを先に読み込むため、PNGの404は発生しない。ユーザー制作テーマはPNGを先に読み込む。`meadow` または `cyber` をPNGへ差し替える場合は、[ThemeCatalog.js](../src/ui/ThemeCatalog.js) の対象テーマの形式順を `['png', 'svg']` に変更する。

定義から実際のタイルを生成するとき、`idPrefix` と通し番号を組み合わせた一意なIDを発行する。例：`thin-straight-road-001`。

タイル内の特徴領域には、生成時に `tileId:featureType:groupIndex` 形式の一意な特徴IDを発行する。例：`thin-straight-road-001:road:0`。

`roadTerminals` の終端には以下を指定する。

- `{ kind: "edge", edge: "DA" }`：盤面上の別タイルへ接続可能な道端（シンの例）
- `{ kind: "city", cityGroup: 0 }`：同じタイル内の都市で終わる道端
- `{ kind: "intersection", intersectionId: "junction-0" }`：同じタイル内の交差点で終わる道端
- `{ kind: "monastery" }`：同じタイル内の修道院で終わる道端

交差点はタイル内で道路を相互接続しない。各道路グループが同じ `intersectionId` へ終端として接続するだけであり、道路の完成条件上は終端として扱う。
修道院も道路を相互接続しない終端として扱う。修道院へ到達する道路は、もう一方の外部道端が接続された時点で完成する。
修道院から道が1本出るタイルでは、道以外の3辺に接する草原を1つの草原領域として定義する。

#### 定義例

```js
{
  idPrefix: "thin-straight-road",
  count: 2,
  shape: "thin",
  edgeTerrain: { AB: "R", BC: "F", CD: "R", DA: "F" },
  featureGroups: {
    city: [],
    road: [["AB", "CD"]],
    field: [
      { id: "field-0", boundaryEdges: ["BC"] },
      { id: "field-1", boundaryEdges: ["DA"] }
    ]
  },
  roadTerminals: {
    0: [{ kind: "edge", edge: "AB" }, { kind: "edge", edge: "CD" }]
  },
  fieldCityAdjacency: { 0: [], 1: [] },
  hasMonastery: false,
  hasCrest: false
}
```

### 試作タイルセット

初期の描画・配置検証用として、次の25枚を定義する。方向はデフォルト向きの辺名であり、タイル回転により盤面上の向きは変わる。

| `idPrefix` | 枚数 | 地形設定 |
| --- | ---: | --- |
| `straight-road` | 4 | シン例: `edgeTerrain: { AB:R, BC:F, CD:R, DA:F }`、`road: [[AB, CD]]`、草原2領域 |
| `curve-road` | 4 | シン例: `edgeTerrain: { AB:R, BC:R, CD:F, DA:F }`、`road: [[AB, BC]]`、草原2領域 |
| `city-one-side` | 4 | シン例: `edgeTerrain: { AB:C, BC:F, CD:F, DA:F }`、`city: [[AB]]` |
| `city-one-side-straight-road` | 2 | シン例: `AB:C, BC:R, CD:F, DA:R`、`city: [[AB]]`、`road: [[DA, BC]]`、草原2領域 |
| `city-one-side-curve-road` | 2 | シン例: `AB:C, BC:R, CD:R, DA:F`、`city: [[AB]]`、`road: [[BC, CD]]`、草原2領域 |
| `city-road-end` | 4 | シン例: `AB:C, BC:R, CD:F, DA:F`、`city: [[AB]]`、`road: [[BC]]`。道のもう一方の終端は同タイル内の都市。草原2領域 |
| `t-junction` | 3 | シン例: `AB:R, BC:R, CD:F, DA:R`、`road: [[AB], [BC], [DA]]`、草原3領域 |
| `monastery-field` | 2 | `hasMonastery: true`、すべて草原 |

### 追加した都市・交差点タイル

以下の種別は、各1枚をシン・ファットそれぞれに追加する。表中の辺名はシンの例で、ファットでは対応する `EF`・`FG`・`GH`・`HE` を用いる。

| `idPrefix` | 都市・道の特徴領域 | 草原領域 |
| --- | --- | ---: |
| `city-four-connected` | 4辺都市が1都市 | 0 |
| `city-three-connected` | `AB/BC/CD` の3辺都市が1都市 | 1 |
| `city-three-road` | 3辺都市が1都市、`DA` の道は都市で終端 | 2 |
| `city-opposite-connected` | `AB/CD` の対向都市が1都市 | 2 |
| `city-opposite-separated` | `AB` と `CD` の対向都市が別々 | 1 |
| `city-adjacent-connected` | `AB/BC` の隣接都市が1都市 | 1 |
| `city-adjacent-curve-road` | 隣接都市が1都市、残る2辺の曲線道 | 2 |
| `city-adjacent-separated` | `AB` と `BC` の隣接都市が別々 | 1 |
| `city-one-t-junction` | `AB` 都市、残る3辺は別々の道で同一交差点に終端 | 3 |
| `cross-junction` | 4辺の道は互いに別で、同一十字交差点に終端 | 4 |

この試作セットではシン12枚・ファット13枚に割り振る。25枚は奇数のため完全な同数にはできず、差は1枚とする。直線道・曲線道・1辺都市・都市終端の道は各2枚ずつ、都市と道の複合タイル・修道院は各1枚ずつを両形状に割り振り、T字路はシン1枚・ファット2枚とする。

この試作セットに左右・上下の反転カードは含めない。すべてデフォルト向きの地形データだけを山札へ入れる。

草原は、道または都市で分断されるごとに別の特徴領域として定義する。直線道・曲線道は都市の有無にかかわらず2領域、T字路は3領域、十字交差点は4領域、対向する2辺の都市と左右の草原は2領域、都市へつながる道を含むタイルは2領域である。各草原領域には独立してミープルを置ける。

各試作タイルの草原領域、都市と草原の隣接、道路終端の詳細は、タイル意匠を作成する時点でこのスキーマに従って定義する。
