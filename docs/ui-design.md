# Penrosanne UIデザイン仕様（本格UI向け草案）

## 目的と適用範囲

タイルを画面上の画像ではなく、盤面上で持ち上げたり置いたりできる薄い物体として感じられるUIを作る。物体感はテーマカラーに依存させず、**厚み・影・持ち上げ・配置**を一貫した表現で成立させる。ゲームの合法配置、得点、手番進行は既存仕様に従い、この文書は表示と操作感を定める。`meadow` の色は本書で指定し、最終的なフォントファイルは後で決める。

UIの見た目と操作演出については、今後この仕様書を既存の試作段階の指示・試作コードの表現より優先する。ルール判定や得点は `docs/rules.md` など各ゲーム仕様を正とする。試作UIと食い違う箇所は、本書に合わせて実装を更新する。

### 参考画像の分析

| 画像 | 観察できる表現 | Penrosanneへの適用 |
| --- | --- | --- |
| 1枚目・盤面全体 | ブロックの上面は平坦で輪郭が明快。下側に単色の側面が見え、盤面上の物体に見える。文字と記号は少数の強い形に絞られている。 | ひし形タイルと主要ボタンに同じ側面の作り方を使う。地形と数字の識別を優先する。 |
| 2枚目・持ち上げ中 | 持ち上げたブロックの上面と側面が分かれ、下の空き位置が着地点として意識できる。 | 手札をつまむと元の場所から垂直に浮く。最寄りの合法候補に着地点の影を置く。 |
| 3枚目・盤面の一部 | 接地中のブロックの側面が、周囲の空きマスとの前後関係を伝えている。 | 設置後は浮き量をゼロに戻し、側面と接地影で盤面との接触を示す。 |

参考画像の四角い盤面配置・記号・配色は模倣しない。シン／ファットのひし形、地形画像、ミープル、確定配置の線に合わせて再構成する。

## 視覚の基本原則

- 形は明瞭な輪郭、単色の上面、明暗が分かれた側面で構成する。色のグラデーション、ガラス風の透過パネル、ぼかし、強いドロップシャドウ、発光は使わない。
- タイルの平面位置はルール判定に使う座標と一致させる。高さは表示専用の値とし、合法配置や当たり判定を変えない。
- 上面にはテーマの地形画像を重ね、少し角を丸めたひし形でクリップする。側面と影は上面の下に描く。地形画像は輪郭の外へ出さない。
- 同じタイルは状態が変わっても形状・厚み・光の方向を変えない。持ち上げ時に変わるのは物体の高さと、接地影からの距離である。
- 色だけで意味を伝えない。タイル、合法候補、確定配置、ミープル、操作ボタンは形や位置でも区別する。

### タイルとミープルの立体感

タイルは従来のひし形を保ち、角を少し丸くした輪郭で地形画像をトリミングする。その輪郭に沿った側面と接地影を追加して、薄い立体物として描く。角丸や側面は見た目だけの処理とし、辺の接続点・配置座標・合法配置を変えない。

ミープルの直立・寝そべり・手元用SVGには、すでに側面を含む立体表現がある。画像をそのまま表示し、タイル用の側面を後付けしたり、画像を色相変換・影レイヤー合成したりしない。プレイヤーが選んだ色番号に対応する完成済みSVGを使用する。

## タイルの物理表現

### 描画レイヤー

奥から、盤面背景 → 合法候補・着地点の影 → タイルの接地影 → 側面 → 上面（地形画像・輪郭） → ミープル → 操作ボタンの順に描く。持ち上げ中のタイルは他のタイルより前面に描く。接するタイル同士で側面が隣の上面を不自然に覆わないようにする。

| 部分 | 接地中 | 持ち上げ中 |
| --- | --- | --- |
| 上面 | 現在のひし形と地形画像。輪郭は明瞭。 | 同じ画像・同じ向き。急に拡大・縮小しない。 |
| 厚み（側面） | 画面下方向へ約3〜5画面px。上面より一段暗い単色。 | 側面の厚さを維持したまま、物体全体を上へ約8〜12画面px移す。 |
| 接地影 | 下方向へ約1〜2画面pxの硬い単色面。 | 盤面側に残し、上面との間隔を広げる。ぼかしを使わない。 |
| 着地点の影 | 表示しない。 | 最寄りの合法候補のひし形に表示。持っているタイルより弱く、確定配置の線と混同しない。 |

数値は通常倍率での初期目安。ズームしても画面上の厚みが不自然に巨大化しないよう画面px基準で調整する。光と側面が見える方向は全タイル・ボタンで統一する。上面と側面には同じ角丸輪郭を使い、辺の接続位置や地形境界は動かさない。

### 状態別の見え方

| 状態 | 表示 |
| --- | --- |
| 手札／待機 | 画面左下の手札置き場で接地。盤上タイルと同じ厚みを持つ。 |
| つまみ始め | 手札上の元の平面位置を保って上に浮く。元位置に硬い影が残る。 |
| 運搬中 | タイルをつまんだ地点とポインターの相対位置を維持して移動する。候補の影は最寄りの合法位置へ移る。 |
| 有効位置で放す | タイル本体が着地点へ短く移動して接地。仮置き状態になり、確定・やり直し・利用可能な回転／反転操作が現れる。 |
| 無効位置で放す／キャンセル | タイルが手札へ短く戻る。候補や手番は変わらない。 |
| 確定 | 仮置きの上面・地形・向きを保持し、操作ボタンを消す。ミープル配置段階へ移る。 |

確定配置の薄い灰色の実線は現在の意味のまま残す。着地点の影はドラッグ中の手札の行き先だけを示す。

## タイルをつまんで置く操作

| 契機 | 挙動 | 時間の目安 |
| --- | --- | ---: |
| 手札タイルを押す | 押した点をタイル内の把持点として記録。**平面位置は動かさず**、物体全体だけを画面上方向へ浮かせる。 | 約100ms |
| 押したまま動かす | 把持点とポインターの相対距離を保ち、移動差分だけタイルを運ぶ。押した瞬間にタイル中心をカーソルへ合わせない。 | 入力に追従 |
| 合法候補に近づく | 最寄りの合法候補を着地点に選び、そこに硬い影を表示。別候補が近くなれば影を切り替える。 | 即時〜短時間 |
| 有効位置で放す | 運搬中の位置から候補位置へ移動し、接地する。到着後に仮置き操作を出す。 | 約100ms |
| 無効位置・画面外で放す／操作を中断する | 手札位置へ戻し、影を消す。 | 約100〜140ms |

浮き上がりと平面移動は別の値として扱う。持ち上げの100ms中に指やマウスが動いても移動差分を失わず、浮き上がりと並行して運ぶ。ドラッグ中の本体は候補位置に瞬間スナップしない。候補への接続感は盤面上の影で示し、離してから約100msで着地点へ動かす。

- 候補影は合法候補だけに表示する。周辺に候補がなければ影を出さない。近い候補が複数ある場合は距離で決め、同距離付近でちらつかないよう切替に小さな余裕を設ける。
- タイルをつかんだ操作中は盤面パンを開始しない。タッチで二本指のピンチへ移るときはタイル操作を安全にキャンセルする。ポインターが画面外へ出ても解放・キャンセルを一度だけ処理する。
- 既存の「候補をクリックして仮置き」「仮置きタイルを別候補へ移す」「右クリックで候補パターンを巡回」も利用可能にする。クリック時には短い接地動作を用い、不要な持ち上げ待ちを入れない。
- 回転・反転後も上面画像、側面、影、ミープルアンカーを同じ向きに更新する。該当候補がない操作ボタンは表示しない。
- ルールエンジンへの配置確定と表示用アニメーションを分け、アニメーション中の二重確定を防ぐ。探索待ちで候補が未確定の間は、確定できるように見せない。

## ブロック型ボタンと画面構成

参考画像下部のブロックを主要な操作ボタンの形として採用する。角を少し丸めた単色の上面、下方向へ約3〜5画面pxずれた濃い側面、短いアイコンまたは1語のラベルで構成する。ホバー時は上面を1〜2px浮かせ、押下時は側面の高さぶん沈める。無効時は彩度だけに頼らず、沈んだ状態と名称で示す。

仮置き後の確定、やり直し、180度回転、地形反転、ミープルを置かない操作はタイルの近くに出す。盤面を遮らず、ズーム・画面端・スマホの狭い画面でも画面内に収める。重要操作の名称は日本語／英語のツールチップとアクセシブル名でも提供する。

盤面を主役にする。手元のタイルと手持ちミープルの個別表示は行わず、タイルは配置候補を選んだときに盤面上で仮置きする。2〜4人の各プレイヤー情報は、1人目を右下、2人目を左下、3人目を左上、4人目を右上へ配置する。手番、山札残数、引き直し等の操作は盤面の中央下部にまとめる。ログは右端から開き、重なるプレイヤー情報は左へ避けて盤面も少し左へ寄せる。スマホではプレイヤー情報を角に保ち、ログを開いた場合は同じ側に重ならないよう縦にずらす。

対局画面はウィンドウ全体を覆う1枚の背景の上に盤面・プレイヤー情報・ボタンを直接配置する。盤面専用の枠や、手札・ミープルを囲う別ウィンドウを設けない。設定は同じ背景色の全画面へ切り替え、ログは必要なときだけ右端に開く。説明文は対局画面へ常設せず、操作名はボタンのラベル・ツールチップで伝える。

## タイポグラフィ

| 用途 | 書体の性格 | 指定方針 |
| --- | --- | --- |
| タイトル、手番、スコア、山札枚数、短いボタンラベル | 太く角ばったピクセル／デジタルゲーム向け。数字は見分けやすい等幅。 | 表示用書体トークンを設け、数字は桁が変わっても位置が揺れないよう等幅数字を使う。 |
| 説明文、設定名、ログ、得点内訳、確認文 | 可読性の高い標準的な日本語サンセリフ体。 | 本文用書体トークンを分け、長文に十分な行間を取る。英語表示でも改行やボタン幅が崩れないようにする。 |

日本語の長文をピクセル書体で埋めない。表示用書体が日本語非対応の場合、和文だけ角ゴシックの太字へフォールバックする。フォントファイル・ライセンス・具体的な文字サイズは画面モックの段階で確定する。

## テーマ化と禁止表現

盤面背景、タイル側面、接地影、着地点の影、文字、ボタン上面、ボタン側面、選択・警告の色は、役割別のデザイントークンにする。テーマ変更では役割間の明度差と可読性を保つ。タイル地形画像とUI全体を同じ色へ固定しない。

### `meadow` テーマの指定色

以下は `meadow` 用の色であり、`cyber` への適用は今回の対象外とする。画像アセットがある地形はその画像を優先し、画像がないときのCanvas描画やUIの対応する面にも同じ色の役割を使う。ここでいうタイルの側面は、ミープルSVG内の側面とは別である。

| 色 | 名称 | 用途 |
| --- | --- | --- |
| `#568500` | グラスグリーン | タイルの草原の色。 |
| `#00513E` | ディープグリーン | タイル側面の基本色。 |
| `#6E5143` | ココアブラウン | タイル側面の代替候補。採用時は全タイルで同じ側面色を用いる。 |
| `#437700` | フォレストグリーン | 草原のグラスグリーンを少し暗くした色。 |
| `#A05F47` | テラコッタ | 都市の色。 |
| `#E6C9B4` | サンドベージュ | 道の色。 |
| `#4A423E` | ダークアース | 都市と草原の境界など、地形を区切る線の色。 |
| `#333333` | チャコール | 汎用的な黒色。文字・記号などに使用。 |
| `#FFFFFF` | ホワイト | 汎用的な白色。文字・記号などに使用。 |
| `#4D746F` | スレートグリーン | 盤面の背景色とゲーム画面全体のメインカラー。将来変更する可能性がある。 |

ミープルのアセットに含まれる12色も使用できる。ただし、その色はプレイヤーの固有色として使われるため、都市・道・候補などの共通UI要素に流用するときは、プレイヤー識別と混同しない用途・表示方法に限る。接地影・着地点の影・ボタン側面の最終的な色と明度は、上記の指定色を基準に画面モックで確認して決める。

色のグラデーション、ぼかし、ガラス風UI、強いドロップシャドウ、大きな発光、過剰なパーティクル・バウンス、汎用Webアプリ風の平面ボタンは採用しない。動きは短く、主として位置と高さで伝え、装飾だけの待機時間を追加しない。

## 実装時の受け入れ条件

1. 盤面の合法候補をクリックすると、その位置にタイルが仮置きされる。仮置きタイルは盤面上でドラッグして別候補へ移動できる。
2. 仮置きタイルをつまむと約100msで浮き、中心がカーソルへ飛ばない。最寄りの合法候補だけに着地点の影が出て、合法候補で離すと約100msで移動する。
3. 持ち上げ中、仮置き、確定後で上面・側面・影の方向と地形画像の向きが一致する。ズーム中とスマホでも破綻しない。
4. ブロック型ボタンは上面と側面を持ち、押すと沈む。操作はマウスとタッチで識別・実行できる。
5. 日本語／英語の長文は本文書体で読みやすく、数字・短い見出しは表示用書体で判別できる。テーマカラーが変わっても情報の優先順位が成立する。
6. 動きを減らす環境設定では浮き・移動を即時完了にしても、着地点・仮置き・確定の状態が分かる。

## 実装メモ（2026-09-24）

対局用のスタイルを `game.css`、仮置き後の持ち上げ・運搬・着地を `src/ui/TileDrag.js` に分離した。画面表示には Chakra Petch、本文と日本語のフォールバックには Noto Sans JP を指定する。フォントを取得できない環境では標準サンセリフへフォールバックする。盤面・ドラッグ中のタイルは共通の `BoardView` の描画を使い、角丸・画像クリップ・側面の形状を揃える。プレイヤー人数は2〜4人から選択でき、個別の手元タイル／残りミープル表示は置かず、全員の情報を盤面の四隅へ分散する。

手元のTHINは表示上だけ90度回して縦長に見せる。手元から持ち上げた表示も同じ向きで始め、着地点へ移動する間に合法候補の向きへ合わせる。手札の回転値と配置規則は変えない。

「私的な都市計画」モードでは、全プレイヤーの情報の付近に3枚の公開手札を横並びで置く。手番による拡大・縮小は行わず、通常モードの手元と同じ寸法を使う。クリックした配置場所に複数の手札が置ける場合は、タイル画像付きの吹き出しで選び、その後に通常の仮置き操作へ進む。ドラッグでは持った手札だけを対象とする。狭い画面ではタイルを縮めず情報と手札をまとめてスクロール可能にし、ログ・ボタンの場所を確保する。

確定配置の順次表示は、追加分が少ないときは従来どおり約120msごとに1枚ずつ表示する。大量に増えたときは表示間隔を短縮し、必要に応じて1回の描画で数枚ずつ追加する。探索結果・表示順を維持しながら、表示段階を約1秒以内・最大48回程度の再描画に抑える。既存の確定配置はアニメーションせず表示を維持する。
